Day 2 continued — OOP PDF test

Tested on OOP PDF I know well. 4/5 answers correct.
Q4 (constructor) hallucinated "surrounded by braces" — 
retrieval was correct, LLM added training knowledge not in PDF.
This is knowledge conflict — small models mix document content 
with their own training. Fix would be a stricter prompt or 
confidence threshold.

Numbers: simple queries (K=2) took 536-620ms LLM time. 
Complex queries (K=4) took 1188-2070ms. 
Adaptive K is directly reducing LLM latency on simple questions.

Day 5

Built: decompose.py splits multi-part queries on "and", 
"also", "versus" into sub-queries, runs each separately, 
merges answers.

Error: none today.

Learned: pronouns break decomposition — "how is it different 
from a method" loses context for "it" when run as standalone 
query. Real fix would be to carry context from first sub-query 
into second. Also cache + decomposition worked together 
automatically without any extra code.

Day 7:
- Switched dataset to HDFC credit card MITC PDF (710 chunks) — real banking document with specific fees and numbers so RAG vs base LLM contrast is clear and verifiable
- Errors: chunk overlap values needed tuning, queries had to be rewritten multiple times to match how the PDF phrases things — "cash advance fee" missed but "cash withdrawal fee or transaction fee" hit
- Learned: every new PDF needs its own query tuning — retrieval depends on how the document words things, not how the user words things; vector search finds meaning but BM25 still needs keyword overlap

Day 8:
- Added query rewriting — LLM rewrites casual user input into formal document-matching language before retrieval
- Rewriting only active in interactive mode, not demo mode (demo queries already well-formed, rewriting was hurting retrieval)
- Error: enabling rewriting on demo queries pulled wrong chunks — "annual fee" rewritten too generically and hit a different card variant's chunk
- Learned: query rewriting helps for casual input but can hurt precision on already-good queries — need to apply it selectively

Day 9:
- Built semantic cache — embeds queries and uses cosine similarity instead of exact string match
- Measured actual similarity scores: exact match = 1.0, paraphrase = 0.55, casual rephrase = 0.46
- Threshold set at 0.75 — below that risks returning wrong cached answers for different questions
- Learned: semantic cache needs a stronger embedding model to bridge paraphrases — all-MiniLM-L6-v2 is too small for this; limitation is model size not the approach
